# Phase 1 Data Model: Investment Committee Domain Model

Eight core entities, one shared `Money` value object, and two closed enumerations,
matching the spec's Key Entities section. All identifiers are `uuid.UUID`, supplied
explicitly by the caller (never auto-generated by the model); all monetary values are
represented by `Money` (a `decimal.Decimal` amount plus a required, ISO 4217-validated
`currency`); the canonical serialized form for every model is a plain dict via Pydantic
v2's `model_dump()` / `model_validate()` (spec Clarifications).

## Money (`aic.domain.money.Money`)

| Field | Type | Required | Notes |
|---|---|---|---|
| `amount` | `Decimal` | Yes | |
| `currency` | `CurrencyCode` (validated `str`) | Yes | Rejected if not a real ISO 4217 code |

A reusable value object bundling an amount with its currency. Carries no arithmetic or
financial-calculation methods — purely a typed container (FR-017; research.md "`Money`
value object for monetary fields").

## Enumerations

### EvidenceType (`aic.domain.enums.EvidenceType`, `StrEnum`)

`FACT`, `CALCULATION`, `ASSUMPTION`, `INTERPRETATION`, `OPINION` — closed set (FR-003).

### Recommendation (`aic.domain.enums.Recommendation`, `StrEnum`)

`BUY`, `WATCH`, `AVOID` — closed set (spec Assumptions, sourced from the constitution's
Investment Decision Principles).

## FinancialSnapshot

| Field | Type | Required | Notes |
|---|---|---|---|
| `as_of` | `date` | Yes | |
| `revenue` | `Money \| None` | No | |
| `operating_income` | `Money \| None` | No | |
| `net_income` | `Money \| None` | No | |
| `free_cash_flow` | `Money \| None` | No | |
| `cash` | `Money \| None` | No | |
| `debt` | `Money \| None` | No | |
| `shares_outstanding` | `Decimal \| None` | No | A share count, not money — no currency |

Validation: every metric beyond `as_of` is independently optional and MUST NOT be
defaulted to `0` or fabricated when absent (FR-013); no ratio/valuation calculation is
performed on these values (FR-004, FR-017). No standalone `currency` field exists —
each populated monetary metric carries its own via `Money`. A model-level validator
requires that every *populated* `Money` metric on one snapshot share the same currency
(rejected with an explicit validation error otherwise), preserving the "one snapshot,
one currency" semantic without a redundant top-level field (research.md "`Money` value
object for monetary fields").

## Relationships summary

```text
Company ──┐
          ├─▶ InvestmentCase ──▶ InvestmentThesis ──▶ Evidence (owned)
FinancialSnapshot(s) ─┘                 │
                                          └─▶ Evidence (case-level pool)

AnalysisAssessment ──▶ Evidence (by evidence_id reference)
ValuationResult ──▶ Evidence (by evidence_id reference)
CommitteeDecision ──▶ Evidence (by evidence_id reference)
CommitteeDecision ──▶ ValuationResult (optional, by valuation_id reference)
CommitteeDecision ──▶ InvestmentThesis (nested reference, when available)
```

`Money` is not part of the relationship graph above — it is a shared value type embedded
directly (not referenced by ID) wherever a monetary field appears (`FinancialSnapshot`'s
metrics, `ValuationResult.estimated_value`).

No entity has a lifecycle or state-transition model — every object is an immutable,
point-in-time record (constructed once, not mutated in place), consistent with this
feature's "shape only, no orchestration" scope.
